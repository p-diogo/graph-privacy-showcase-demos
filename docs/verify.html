Verify it yourself

This page checks the two live demonstrations against Ethereum Sepolia in your browser, talking straight to a public RPC. No API key, no install, and — the point of the exercise — no component from The Graph in the trust path. Everything the index serves is meant to be re-derivable without it. Here it is, re-derived.

1 · The confidential bond

An issuer anchored a bond's lifecycle on-chain as Poseidon commitments and Merkle roots. Values, owners and amounts never touched the chain. These reads ask the contract directly what it actually anchored.

CheckRead from chainResult

Now try to fool it. This asks the bond contract whether a Merkle root is one it anchored. Change any digit and it answers false — the chain will not confirm a root that was never claimed.

2 · The encrypted anchor stream

A record-keeper encrypted ten records client-side and posted only their ciphertext digests, as raw calldata, to a contract that stores nothing and emits nothing. This rebuilds that stream from the transactions themselves and re-computes the hash chain that links each anchor to the one before it.

What this page does and does not establish

  • Establishes: the bond contract holds exactly these commitments and confirms exactly these roots; the anchor stream is contiguous, hash-chained, and every digest is the one the chain carries. All of it re-derived here, from public chain data.
  • Does not establish that the disclosed off-chain records match those anchors. That reconciliation is what the CLIs do, and it needs the disclosed record set — see the bond page and the anchor-stream page.
  • Says nothing about off-chain reality. A record that was never anchored is invisible to every check here. This is not a proof of reserves.
  • Demo-grade, fictional data. The bond id is an ISIN-format string that cannot collide with a real security, and every record, party and amount is invented.
  • This page deliberately avoids the index. Querying the subgraphs on the decentralized network needs a gateway API key, and returns something this page cannot: a signed attestation binding the response to an indexer's stake. That is the CLIs' job.
Reads go to a public RPC of your choosing; change it if you would rather not trust that one — the whole argument here is that you should not have to.
